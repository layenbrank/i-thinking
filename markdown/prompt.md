## 文件组织

文件粒度适中：既不过度拆分，也不过度聚合。

## 改动审查

审查实现时，优先合并进现有逻辑，不要每次改动都叠一层补丁。重复打补丁会让实现变复杂、难维护。

## 命名

命名简洁优雅，避免过长。语义无法一眼看清时，用注释补充说明。

## HTML 结构

HTML 结构保持简洁，避免无用嵌套。每一层容器都要有明确作用。

## 颜色

颜色使用主色；与 Ant Design 相关的样式，优先使用其 CSS Variable key。

## Git 提交

1. 查看当前 git 改动，生成提交信息。
2. 需要时按主题分批提交。
3. client 版本升级使用 `bump:client`，以触发 client tag release 发布。
4. 版本升级，以触发 tag release 发布。
