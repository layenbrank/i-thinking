# audit · 事件与审计

统一的领域事件写入（outbox）与消费去重（consumed_event）：所有「先落库、后处理」的审计与
异步副作用都经由本 crate。

## 数据所有权

| 表 | 说明 |
| --- | --- |
| `outbox` | 待发布事件（同一业务事务内追加写入，发布者只读已提交行）。 |
| `consumed_event` | 消费端幂等去重（复合主键）。 |

## 对外接口

- `Event`：事件载荷与表列一一对应的领域类型（tenant、aggregate、type、payload、occurredAt …）。
- `append(tx, &Event)`：在**调用方的事务**内追加事件，保证业务写入与事件写入同生共死。
- 发布/消费（P4）：读取未发布事件、推进 `publishedAt`、按消费方记录去重。

## 边界约束

- 只追加：事件内容不可更新、不可删除；唯一允许的列变更是发布标记。
- 不依赖 HTTP 框架；不依赖 `service`（R1）。
- 不 JOIN 其他 crate 的表，不做跨边界副作用（发布由 `service` 的 worker 驱动）。
- 事件写入必须与业务写入在同一事务；不允许在事务外单独写 outbox。
